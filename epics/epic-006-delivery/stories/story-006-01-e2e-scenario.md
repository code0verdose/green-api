# STORY-006-01 — E2E сценария ТЗ для MAX и Telegram

**Как** ревьюер **хочу** один тест, который проходит весь сценарий ТЗ,
**чтобы** доверять, что всё работает, без доступа к живому инстансу.

## Подход

Playwright перехватывает запросы к `*.api.green-api.com` (`page.route`) и отвечает по
документации GREEN-API. Мок-сервер хранит очередь уведомлений: после `SendMessage` в неё кладётся
`outgoingMessageStatus`, затем «ответ собеседника» — `incomingMessageReceived`.

## Acceptance

- Для MAX и для Telegram: вход → новый чат → отправка → статус «доставлено» → ответ собеседника в ленте.
- Ошибка входа (401) показывает текст ошибки.
- Мобильный профиль: список → чат → «назад».
- Каждое уведомление удалено из мок-очереди (`DeleteNotification` вызван на каждый `receiptId`).

## DoD

`pnpm e2e` зелёный локально и в CI.
