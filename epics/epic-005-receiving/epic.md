# EPIC-005 — Получение сообщений

## Зачем

ТЗ: «Получатель отвечает на сообщение в мессенджере MAX. Пользователь видит ответ получателя
в чате»; «получение сообщений реализовать методом … technology-http-api».

## Факты из документации GREEN-API

- Получение — два вызова по очереди: `ReceiveNotification` (одно уведомление или `null` по таймауту)
  и `DeleteNotification` (подтверждение по `receiptId`). Без удаления следующий вызов вернёт то же уведомление.
- `receiveTimeout` — от 5 до 60 с, по умолчанию 5. Очередь FIFO, хранение 24 часа.
- Лимит 100 запросов/с на каждый метод.
- `DeleteNotification` может вернуть `{ result: false }` (уже удалено) или 500
  «Cannot read properties of undefined (reading 'findUnAckedMessage')» — удалять нечего.

## Scope

**In:** long polling с отменой и экспоненциальной паузой при ошибках, разбор всех типов
уведомлений, дедупликация, создание чата при входящем от нового собеседника, один опрашивающий
на инстанс (Web Locks), индикатор соединения.

**Out:** webhook, история с сервера, медиа (кроме заглушки «не поддерживается»).
