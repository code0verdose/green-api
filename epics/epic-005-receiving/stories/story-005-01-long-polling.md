# STORY-005-01 — Надёжный long polling

**Как** оператор **хочу** видеть ответы без перезагрузки и без пропусков,
**чтобы** не пропустить сообщение клиента.

## Алгоритм

```
пока поллер запущен:
  ответ = ReceiveNotification(receiveTimeout = 20)
  если ответ == null → следующий круг сразу
  иначе:
    обработать(ответ.body)        — ошибка обработчика логируется и НЕ блокирует очередь
    DeleteNotification(ответ.receiptId)
  ошибка сети / 5xx / 429 → пауза 1 → 2 → 4 … 30 с (+ джиттер), затем снова
  401 / 403              → остановка, выход из сессии
  400 «webhook url is set» → остановка, баннер с инструкцией
```

Удаление идёт **после** обработки: если вкладку закрыли между ними, уведомление придёт снова, а
дедупликация по `idMessage` не даст ему задвоиться (at-least-once + идемпотентный обработчик).

## Acceptance

- **Given** уведомление в очереди, **then** оно обработано и удалено ровно один раз.
- **Given** обработчик бросил исключение, **then** уведомление всё равно удалено, поллер жив.
- **Given** 3 сетевые ошибки подряд, **then** паузы растут: ~1 с, ~2 с, ~4 с; после успеха сбрасываются.
- **Given** выход из сессии или уход со страницы, **then** текущий запрос отменён (`AbortController`), новых нет.
- **Given** 401, **then** поллер остановлен и пользователь разлогинен.
- **Given** 400 webhook, **then** поллер остановлен, баннер, кнопка «Повторить».
- Индикатор в заголовке списка чатов: «Подключение…» / «В сети» / «Нет связи, переподключаемся…» /
  «Получение сообщений остановлено» (+ «Повторить») / «Сообщения принимает другая вкладка».

## DoD

Юнит-тесты поллера на фейковых таймерах (все ветки), зелёный гейт.
