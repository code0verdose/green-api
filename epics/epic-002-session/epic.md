# EPIC-002 — Вход по учётным данным GREEN-API

## Зачем

ТЗ: «Пользователь переходит на сайт чата и вводит свои учётные данные из системы GREEN-API
(idInstance, apiTokenInstance)». Без проверенных учётных данных все остальные вызовы бессмысленны,
а ошибка «401» без объяснения — худший первый опыт.

## Scope

**In:** форма входа (мессенджер, `idInstance`, `apiTokenInstance`, `apiUrl`), проверка
`getStateInstance`, человекочитаемые ошибки, сессия в `sessionStorage`, guard маршрутов, выход,
диагностика инстанса через `getSettings` и баннер состояния.

**Out:** авторизация самого инстанса по QR (делается в личном кабинете GREEN-API), смена токена,
`SetSettings`.

## Acceptance

- Неверный токен → «Неверный idInstance или apiTokenInstance», форма не очищается.
- Инстанс не авторизован → объяснение и ссылка на личный кабинет, вход не выполняется.
- После входа перезагрузка вкладки не разлогинивает; закрытие вкладки — разлогинивает.
- Неавторизованный заход на `/` → редирект на `/login`, после входа — обратно.
