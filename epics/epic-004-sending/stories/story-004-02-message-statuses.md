# STORY-004-02 — Статусы исходящих и повтор

**Как** оператор **хочу** видеть, дошло ли сообщение и прочитано ли оно,
**чтобы** знать, ждать ли ответа.

## Статусы

| Статус      | Значок                  | Откуда                                                                                     |
| ----------- | ----------------------- | ------------------------------------------------------------------------------------------ |
| `pending`   | часы                    | отправка в полёте                                                                          |
| `sent`      | ✓                       | ответ `SendMessage` с `idMessage`                                                          |
| `delivered` | ✓✓                      | `outgoingMessageStatus.status = delivered`                                                 |
| `read`      | ✓✓ акцентом             | `outgoingMessageStatus.status = read`                                                      |
| `failed`    | ! красным + «Повторить» | ошибка запроса, или `outgoingMessageStatus.status` = `failed` / `noAccount` / `notInGroup` |

Статус не откатывается назад: `read` не превращается в `delivered`, если уведомления пришли не по порядку.

## Acceptance

- **Given** `failed`, **when** «Повторить», **then** тот же текст уходит заново, статус `pending`.
- **Given** уведомление `noAccount`, **then** `failed` с подсказкой «Получатель не найден — создайте чат заново».
- **Given** `read` пришёл раньше `delivered`, **then** остаётся `read`.

## DoD

Тесты редьюсера статусов (все переходы), компонентный тест пузыря, зелёный гейт.
