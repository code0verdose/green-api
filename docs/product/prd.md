# PRD — GREEN-API Chat

> Веб-клиент для отправки и получения текстовых сообщений в MAX и Telegram через сервис GREEN-API.
> Тестовое задание «Фронтенд разработчик React» (GREEN-API).

## 1. Проблема

Разработчику или оператору, у которого есть инстанс GREEN-API, нужен простой способ переписываться
с людьми в мессенджере прямо из браузера: без своего бэкенда, без Postman и без чтения JSON.
Сейчас для этого приходится вызывать HTTP API вручную и разбирать очередь уведомлений руками.

## 2. Цель

Дать минимальный, но надёжный чат в стиле web.max.ru:

1. войти по учётным данным инстанса GREEN-API;
2. создать чат по номеру телефона;
3. отправить текстовое сообщение;
4. увидеть ответ собеседника в том же окне.

## 5. Скоуп (MoSCoW)

### Must

- Вход по `idInstance` + `apiTokenInstance` (+ `apiUrl` из личного кабинета) с проверкой через `getStateInstance`.
- Выбор мессенджера: MAX или Telegram.
- Создание чата по номеру телефона; номер превращается в `chatId` методом `CheckAccount`.
- Отправка текста методом `SendMessage`, лимит длины по мессенджеру (MAX — 4000, Telegram — 4096).
- Получение входящих методом `ReceiveNotification` с обязательным `DeleteNotification` после обработки.
- Показ ответа собеседника в чате.
- Выход с очисткой учётных данных.

### Should

- Статусы исходящих: отправляется, отправлено, доставлено, прочитано, ошибка; повтор отправки.
- Входящее от нового собеседника автоматически создаёт чат.
- Счётчик непрочитанных и сортировка чатов по последнему сообщению.
- Диагностика инстанса: не авторизован, задан `webhookUrl` (HTTP API тогда не работает), выключены входящие уведомления.
- Сохранение истории в браузере, чтобы перезагрузка страницы не стирала переписку.
- Telegram: создание чата по `@username`, а не только по номеру.

### Could

- Мобильная раскладка (список и чат на отдельных экранах).
- Один опрашивающий на инстанс, чтобы вкладки не делили очередь уведомлений между собой.

### Won't (в этой версии)

- Медиа, файлы, голосовые, стикеры, реакции, редактирование и удаление сообщений.
- Групповые чаты.
- Загрузка истории с сервера (`GetChatHistory`) — ТЗ требует получение через HTTP API уведомлений.
- Webhook-доставка (нужен свой сервер).
- Тёмная тема, мультиязычность, поиск по чатам.
- WhatsApp — в ТЗ указан как запасной вариант, не нужен при наличии MAX и Telegram.

## 6. Пользовательский сценарий (из ТЗ)

```
Вход → ввод idInstance / apiTokenInstance / apiUrl → проверка инстанса
     → «Новый чат» → ввод номера → CheckAccount → чат открыт
     → ввод текста → SendMessage → сообщение в ленте со статусом
     → собеседник отвечает в MAX/Telegram
     → ReceiveNotification → ответ в ленте → DeleteNotification
```

| ------------------------------------------------ | --------------------------------------------------------------- | ---------------------------------------------------------------------------------- |

| Покрытие кода тестами                            | строки ≥ 90 %, ветки ≥ 85 %                                     | `pnpm test:coverage` в CI                                                          |

## 8. Ограничения и риски

| Риск                                                                                                             | Влияние                                      | Митигация                                                                                                            |
| ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Токен инстанса хранится в браузере                                                                               | Утечка токена при XSS                        | Только `sessionStorage`, CSP с белым списком хостов GREEN-API, React экранирует вывод, нет `dangerouslySetInnerHTML` |
| `apiUrl` нельзя вычислить по `idInstance` (пример из документации: хост `3100` обслуживает инстанс `3000000001`) | Неверный хост → вход не проходит             | Поле `apiUrl` в форме, подсказка «скопируйте из личного кабинета», валидация хоста                                   |
| Тариф Developer: 3 чата в месяц, 100 проверок `CheckAccount`                                                     | Пользователь упрётся в лимит при тестах      | Обработка `quotaExceeded` и кода 466 понятным сообщением                                                             |
| Если задан `webhookUrl`, `ReceiveNotification` отвечает ошибкой 400                                              | Входящие не приходят                         | Диагностика через `getSettings` + остановка поллера с объяснением                                                    |
| Две вкладки делят одну очередь уведомлений                                                                       | Часть сообщений «пропадает» в другой вкладке | Web Locks: очередь инстанса опрашивает одна вкладка, остальные синхронизируются через `storage`                      |
| Номер в MAX → только РФ (7) и РБ (375) для `CheckAccount`                                                        | Нельзя создать чат с иностранным номером     | Валидация номера по правилам мессенджера с понятной ошибкой                                                          |
