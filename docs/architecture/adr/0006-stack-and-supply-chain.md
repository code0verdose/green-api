# ADR-0006 — Стек и защита цепочки поставок

- **Статус:** принято
- **Дата:** 2026-10-05

## Решение

| Слой                 | Выбор                                                                                      | Почему                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| Сборка               | Vite 8                                                                                     | быстрый dev-сервер, нативная поддержка CSS Modules                         |
| UI                   | React 19 + TypeScript 6 (strict, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`) | ТЗ требует React; строгие типы ловят ошибки на границах API                |
| UI-kit               | Mantine 9 + CSS Modules + `postcss-preset-mantine`                                         | готовые доступные компоненты; стили — токены в CSS, без Tailwind           |
| Маршрутизация        | TanStack Router (file-based)                                                               | типобезопасные пути и параметры, guard в `beforeLoad`                      |
| Серверное состояние  | TanStack Query 5                                                                           | кеш состояния/настроек инстанса, мутации с единой обработкой ошибок        |
| Клиентское состояние | zustand 5 + `persist`                                                                      | история чатов и сессия, доступные и из React, и из guard'ов роутера        |
| Валидация            | Zod 4                                                                                      | схема — источник типа; проверка на границах (формы, ответы API, хранилище) |
| Тесты                | Vitest 5 + Testing Library + MSW 3 + jsdom 30; Playwright                                  | юнит/компонент — с моком сети; e2e — на прод-сборке                        |
| Пакетный менеджер    | pnpm 12                                                                                    | строгий `node_modules`, `minimumReleaseAge`, запрет install-скриптов       |

**TypeScript 6.0, а не 7.x:** `typescript-eslint` 8.x поддерживает TypeScript `< 6.1` (сверено с
8.71.1 на 2026-10-05). Dependabot не предлагает TypeScript `>=6.1.0`, пока это так.

**Node 22 и `@types/node` 22.** `engines.node` = `>=22.22.2` объявляет нижнюю границу, которую
требуют jsdom 30 (`^22.22.2 || ^24.15.0 || >=26.0.0`) и MSW 3 (`>=22.12`). pnpm её не проверяет
(`engineStrict` не включён): на более старой Node установка пройдёт, а упадут тесты.
`.nvmrc` = `22`, а CI ставит Node с `check-latest: true`, то есть последний выпуск линии 22.
Закрепить минор (`22.22`) нельзя: внутри мажора Node выходит линейно, и линия 22.22.x не
получила security-релизы 22.23.0 и 22.23.2.
Типы Node описывают ту версию, на которой код работает, а не самую свежую: с `@types/node` 26
проверка типов пропустила бы API, которого в Node 22 нет. Мажоры `@types/node` Dependabot не
предлагает; их поднимают вместе с `.nvmrc`.

## Защита цепочки поставок

`pnpm-workspace.yaml`:

- `minimumReleaseAge: 10080` — версии моложе 7 дней не ставятся. Свежие релизы — окно, в котором
  обычно ловят скомпрометированные пакеты. На 2026-10-05 это отсекло, например, `@mantine/*@9.7.0`
  и `@vitejs/plugin-react@6.1.2`, опубликованные в тот же день.
- `allowBuilds: {}` — install-скрипты зависимостей запрещены, разрешённых нет. У MSW 2 был
  postinstall (копия браузерного воркера), у MSW 3 его нет.
- `pnpm audit` — 0 известных уязвимостей на момент фиксации стека.
- `peerDependencyRules.allowedVersions` разрешает `msw` 3 для `@vitest/mocker`: там это
  необязательная зависимость режима тестов в браузере, а тесты идут в jsdom через `msw/node`.
  Убрать правило, когда `@vitest/mocker` примет `^3`.
- GitHub Actions закреплены полными SHA коммитов с комментарием версии: перенесённый тег не
  подменит код сборки. Раннеры закреплены версией (`ubuntu-24.04`): `ubuntu-latest` сам
  переезжает на новый выпуск, а Playwright ставит системные пакеты под конкретный дистрибутив.
- `.github/dependabot.yml` обновляет и actions, и npm-пакеты с той же недельной выдержкой
  (`cooldown: 7`). Минорные и патч-обновления идут одним PR, каждый мажор — отдельным: один
  ломающий релиз не задерживает остальные. Правила `ignore` действуют и на security-обновления:
  для `typescript` и `@types/node` (только инструменты разработки) это принято осознанно.

## Архитектура кода

FSD-вариант «units»: `app → pages → widgets → units → shared`, зависимости только вниз.
Границы проверяет ESLint (`no-restricted-imports`): нельзя импортировать вышележащий слой, вглубь
чужого юнита мимо его `index.ts` и вглубь `shared` мимо namespace-реэкспорта.

## Принятые ограничения

- **Вендорные библиотеки не вынесены в отдельные чанки (`manualChunks`).** Маршруты делятся
  автоматически (`autoCodeSplitting`), но React, Mantine и TanStack лежат в двух крупных чанках:
  `index` ~390 КБ (125 КБ gzip) и `session` ~356 КБ (110 КБ gzip). Замер `vite build` от 2026-10-05.
  Любой релиз меняет их хеши, поэтому браузер скачивает их заново. Для тестового задания это
  допустимо; при регулярных релизах стоит выделить стабильный вендорный чанк.
- **Предупреждение `MaxListenersExceededWarning` в юнит-тестах.** Его выдаёт `@mswjs/interceptors`
  0.45.5 (зависимость MSW 3): на каждый подменённый ответ он вешает одноразовые слушатели на
  переиспользуемый TLS-сокет. Это шум тестового окружения, в сборку приложения MSW не попадает.
  Предупреждение не заглушено, чтобы не спрятать настоящую утечку; проверить заново при
  следующем обновлении MSW.
- **Текст неожиданной ошибки показывается как есть.** Ошибки GREEN-API переводятся в понятные
  сообщения (`getErrorMessage`), но исключение, которое не является `GreenApiError` (ошибка в
  самом коде), попадёт в тост своим `message`, обычно по-английски. Токена в нём нет: ошибки
  клиента не содержат URL.
