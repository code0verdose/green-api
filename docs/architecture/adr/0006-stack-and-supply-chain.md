# ADR-0006 — Стек и защита цепочки поставок

- **Статус:** принято
- **Дата:** 2026-10-05

## Решение

| Слой                 | Выбор                                                                                      | Почему                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| Сборка               | Vite 8                                                                                     | быстрый dev-сервер, нативная поддержка CSS Modules                         |
| UI                   | React 19 + TypeScript 6 (strict, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`) | ТЗ требует React; строгие типы ловят ошибки на границах API                |
| UI-kit               | Mantine 9 + CSS Modules + `postcss-preset-mantine`                                         | готовые доступные компоненты; стили — токены в CSS, без Tailwind           |
| Маршрутизация        | TanStack Router (file-based)                                                               | типобезопасные пути и параметры, guard в `beforeLoad`                      |
| Серверное состояние  | TanStack Query 5                                                                           | кеш состояния/настроек инстанса, мутации с единой обработкой ошибок        |
| Клиентское состояние | zustand 5 + `persist`                                                                      | история чатов и сессия, доступные и из React, и из guard'ов роутера        |
| Валидация            | Zod 4                                                                                      | схема — источник типа; проверка на границах (формы, ответы API, хранилище) |
| Тесты                | Vitest 5 + Testing Library + MSW 2; Playwright                                             | юнит/компонент — с моком сети; e2e — на прод-сборке                        |
| Пакетный менеджер    | pnpm 12                                                                                    | строгий `node_modules`, `minimumReleaseAge`, запрет install-скриптов       |

**TypeScript 6.0, а не 7.x:** `typescript-eslint` 8.x поддерживает TypeScript `< 6.1`.

## Защита цепочки поставок

`pnpm-workspace.yaml`:

- `minimumReleaseAge: 10080` — версии моложе 7 дней не ставятся. Свежие релизы — окно, в котором
  обычно ловят скомпрометированные пакеты. На 2026-10-05 это отсекло, например, `@mantine/*@9.7.0`
  и `@vitejs/plugin-react@6.1.2`, опубликованные в тот же день.
- `allowBuilds` — install-скрипты запрещены всем; `msw` тоже (его postinstall нужен только для
  браузерного воркера, тесты используют `msw/node`).
- `pnpm audit` — 0 известных уязвимостей на момент фиксации стека.
- GitHub Actions закреплены полными SHA коммитов с комментарием версии: перенесённый тег не
  подменит код сборки. `.github/dependabot.yml` обновляет и actions, и npm-пакеты с той же
  недельной выдержкой (`cooldown: 7`).

## Архитектура кода

FSD-вариант «units»: `app → pages → widgets → units → shared`, зависимости только вниз.
Границы проверяет ESLint (`no-restricted-imports`): нельзя импортировать вышележащий слой, вглубь
чужого юнита мимо его `index.ts` и вглубь `shared` мимо namespace-реэкспорта.

## Принятые ограничения

- **Вендорные библиотеки не вынесены в отдельные чанки (`manualChunks`).** Маршруты делятся
  автоматически (`autoCodeSplitting`), но React, Mantine и TanStack лежат в двух крупных чанках:
  `index` ~390 КБ (125 КБ gzip) и `session` ~356 КБ (110 КБ gzip). Замер `vite build` от 2026-10-05.
  Любой релиз меняет их хеши, поэтому браузер скачивает их заново. Для тестового задания это
  допустимо; при регулярных релизах стоит выделить стабильный вендорный чанк.
- **Текст неожиданной ошибки показывается как есть.** Ошибки GREEN-API переводятся в понятные
  сообщения (`getErrorMessage`), но исключение, которое не является `GreenApiError` (ошибка в
  самом коде), попадёт в тост своим `message`, обычно по-английски. Токена в нём нет: ошибки
  клиента не содержат URL.
